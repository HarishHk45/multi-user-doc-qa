# Multi-User Document Search & Conversational Q&A

A small Retrieval-Augmented-Generation system over a set of earnings-call transcript PDFs, with per-user document access control and conversational follow-up support, driven by a Streamlit UI.

## How it works

- **Documents**: five synthetic Q4 earnings-call transcripts for fictional companies (`data/pdfs/`), generated by `app/generate_sample_pdfs.py`. They are invented for this demo, not real filings.
- **Access control**: `app/config.py` maps dummy user emails to the companies they may query (`USERS`). No real authentication — this simulates it, per the assignment's own scope.
- **Isolation**: each company gets its own FAISS vector index (`app/ingest.py`, stored under `data/index/<company_id>/`). A query only ever loads the indexes for the companies the logged-in user is allowed to see — there's no single shared index with a filter that could leak across users if a filter expression were wrong.
- **Conversation**: `app/qa_engine.py` keeps a per-user chat history server-side. A follow-up question is first rewritten into a standalone question using that history (so "what about their margins?" resolves correctly), then used to retrieve chunks and answer.
- **Multi-user**: the `QAEngine` is a single shared instance (cached by Streamlit) holding one history per user email, so concurrent users' conversations and retrieved documents never mix.
- **UI**: `app/streamlit_app.py` — pick or type a user email to "log in", see which companies that user can access, then chat.

## Setup

Requires Python 3.12+ and an API key for an LLM (OpenAI by default, or Anthropic/Claude as an alternative).

```bash
# 1. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Configure your LLM key
cp .env.example .env
# edit .env and set OPENAI_API_KEY (or switch LLM_PROVIDER=anthropic and set ANTHROPIC_API_KEY)

# 4. Generate the sample PDFs (already included in data/pdfs/, but reproducible)
python app/generate_sample_pdfs.py

# 5. Build the per-company vector indexes (must be re-run after any PDF change)
python app/ingest.py

# 6. Run the app
streamlit run app/streamlit_app.py
```

Open the URL Streamlit prints (default `http://localhost:8501`).

### Verifying setup without an API key

`app/test_retrieval.py` exercises index loading, per-user access mapping, and similarity search without calling any LLM — useful to confirm steps 4–5 worked:

```bash
cd app && python test_retrieval.py
```

## Demo users

| Email | Can query |
|---|---|
| `alice@email.com` | NovaPeak Technologies |
| `bob@email.com` | Beacon Health Systems, Cascade Energy Partners |
| `charlie@email.com` | Dover Robotics, Everline Logistics |

You can also type any other email in the UI; an email not in `app/config.py`'s `USERS` dict has no document access and the system will say so rather than searching anything.

## Suggested demo script

1. Log in as `alice@email.com`, ask "What was the Q4 revenue?" — answer should cite NovaPeak Technologies figures only.
2. Log out, log in as `charlie@email.com`, ask the same question — answer should cite Dover Robotics and/or Everline Logistics, never NovaPeak (charlie has no access to it).
3. As `bob@email.com`, ask "What was Beacon's adjusted EBITDA margin?" then follow up with "How does that compare to the prior year?" — the second answer should resolve "that" using the conversation history, without having to repeat "Beacon" or "adjusted EBITDA margin."
4. Open two browser tabs logged in as two different users at once to show queries don't interfere with each other.
5. Use "New conversation" to show history resets, and point to `app/config.py`'s `USERS` map and the per-company index loading in `app/qa_engine.py` to explain how isolation is enforced structurally, not just by a UI filter.

## Project layout

```
app/
  config.py              company + dummy-user access-control config
  generate_sample_pdfs.py  builds the synthetic sample PDFs
  ingest.py               chunks each PDF and builds its FAISS index
  qa_engine.py            retrieval, conversation history, LLM call
  streamlit_app.py        UI: login, chat, sources, per-user sidebar
  test_retrieval.py       no-API-key smoke test for ingestion + isolation
data/
  pdfs/                   the 5 sample transcripts (committed)
  index/                  generated FAISS indexes (not committed; run ingest.py)
```

## Notes and limitations

- The sample documents are synthetic, invented transcripts for fictional companies — built this way so the dataset is self-contained and doesn't depend on scraping real investor-relations sites.
- "Simultaneous access" is demonstrated via Streamlit's per-browser-session state plus the engine's per-email history map; this is a single-process demo, not a production multi-tenant deployment.
- Swap `LLM_PROVIDER` between `openai` and `anthropic` in `.env` depending on which API key you have.
